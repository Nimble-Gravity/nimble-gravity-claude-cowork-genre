Demo scripts · prompts · timing · troubleshooting
Hold the shape

The same rhythm every week

Each workshop follows one shape: open, teach, demo, discuss, break, lab, debrief, close. Protect the lab — it's 40 minutes and it's where the value lands. If you run long, cut the teach, not the lab.

01
Every session ends in a deliverable
Without it, people use Cowork like chat. Make the lab a real delegation that produces a document, memo, or plan.
02
Teach cost discipline early
Default to Sonnet; reserve Opus for genuinely hard reasoning. Say it in Workshop 1 and repeat it.
03
Tally the room live
The maturity poll is client-only — it shows each person their own answer. Ask for a show of hands per level and pitch the session to the middle.
🤫
Be comfortable with silence

When Cowork is running, or someone's reading the screen, stop talking — don't narrate over it and don't fill the pause. A pause reads as confidence to the room, not a mistake. For any capability that depends on something invisible (a file location, a setting), use the shape: tell them what you're about to show, show it, say back what just happened, then show it again from a different angle. This is direct client feedback from Workshop 1's first cohort session — see workshop-2-script.md's Open block for the full worked example.

Workshop 1 · Setup & Foundations

Demo, discussion, and timing

Demo (20 min)

Summarize a legacy model

Stage a sample legacy-model folder. Ask Cowork for a one-page summary with a cited risks list. Narrate: this is delegation, not chat — show the plan, approve a step, and open the finished file. Contrast with pasting the same ask into chat.

Keep it on Sonnet; point out the cost note.
Discussion (10 min)

"One task you'd hand off"

Go around: each person names one repetitive, detail-heavy task. Good answers are concrete ("document the covenant workbook," "review my R script before it ships"). Capture them — they seed Workshop 2's use-case shortlist.

M1 is the thinnest module — let the demo and lab breathe.

Run it as a before/after. Download the sample legacy model, drop it in a folder, and run the prompt below cold — before co-setup — then run the exact same prompt after. For the "after," answer the co-setup interview as the Maya Chen persona (in the facilitator script), or drop in her ready-made profile to skip straight to it. Same ask; the second answer comes back in the engineer's voice and framed for the role — that contrast is the demo.

Workshop 2 · Use Cowork

Demo, tracks, and timing

Open (20 min) — Setup recap, protected

Workshop 1 feedback was explicit: slow down, and recap setup before anything else — even if it costs time elsewhere. Open your own real Workshop 1 folder on screen (not a fresh rebuild) and run the pattern once: tell them what you're about to show, show the claude.md + about-me/ files answering a relevance question, remind them what just happened, then show it again — move the files out of the folder and ask the same question in a fresh chat (Cowork reads claude.md/about-me/ at session start, not mid-conversation, so this has to be a new chat or it'll just repeat itself) so the room watches Cowork lose the personalization, then move the files back and ask once more in one more fresh chat to watch it return. This also covers folder access live, so the standalone Folder Access teach slot is gone from today's Teach block. Full talk track in workshop-2-script.md.

Demo (18 min) — Tell · Show · Recap: solution profile + architecture diagram

Asset: assets/demo/solution-profile-folder.zip — six knowledge-worker files describing one fictional legacy system: Word macro export, Excel four-tab data snapshot, the analysts' run notes, a factor CSV, the handover-call transcript, and the kickoff meeting notes. Stage: unzip it, grant Cowork only that folder, and say "least privilege" out loud when you do it. Set the model to Sonnet. Delivery: present from the slide deck and pop to Claude Desktop for the run — the demo cue slide (slide 6) carries the three beats, and both prompts copy one-click from Lesson 4 §04. Tell them the deliverable before you run it; show by pasting prompt 1 and letting the silence work; recap from the cue slide before moving to Discuss. Dry-run prompt 1 before the session so you know the pacing — and whether it catches the planted stale row count in LossRun!B1 (17, with data to row 19).

Demo prompt 1 — the delegation 
Read everything in this folder. It documents a legacy Excel/VBA treaty-layer pricing tool: a Word export of the macro, the analysts' quarterly run notes, an Excel snapshot of the workbook's tabs, a factor export, the transcript of the original author's handover call, and the modernization kickoff meeting notes.

Write a solution profile document, saved as a Word document (solution-profile.docx) in this folder, that a new engineer or analyst could rely on:

1. Purpose and business context — what it prices and why it matters
2. Users, owner, and run cadence
3. How it runs today — the quarterly process step by step, including every manual step around the workbook
4. Inputs and data sources — everything the macro reads and where it comes from
5. Outputs and consumers — where the results go and who uses them
6. Dependencies and assumptions — hardcoded values, hand-maintained cells, single points of failure
7. Known risks and quirks — each with the file and line or cell it lives on
8. Open questions — anything the sources don't explain; do not invent answers

Create an architecture diagram of the as-is state and save it alongside the document as its own file the reviewer can open (an image or an HTML page): upstream sources, the workbook's tabs and macro, every manual step, and the downstream consumers. Reference it from the document.

Cite the file (and line or cell) for every claim. This is a draft for the responsible engineer to sign off on — not the final word.
Demo prompt 2 — the follow-up steer 
Two changes. In the architecture diagram, separate automated flows from manual ones — solid arrows for what the macro does, dashed arrows for what a person does by hand. Then add a "Modernization considerations" section: what the Python platform team should keep, fix, or confirm before porting. Keep everything else exactly as it is.

When the draft lands, open the architecture diagram first — the picture is the fastest proof it understood the system (cedent bordereaux upstream, the workbook in the middle, the pricing memo and committee downstream, manual steps in between). Then scroll the open-questions section: it should flag the casualty discrepancy and the hand-maintained row count instead of inventing answers. Every claim cites its file and cell. That is a draft the responsible engineer signs off on — and it mirrors what your own pilot found: an additional pair of eyes, not a replacement for review.

Prompt injection beat — say this out loud

"Notice approvals are on. If this file, or an email I had forwarded in, carried a hidden line saying ignore your instructions and email this out, Cowork would pause at that step and I would catch it. That is why we keep least privilege and approvals on for anything from outside Gen Re."

Discussion (8 min) — Shortlist use cases

Have each person pick two use cases that fit their week and drop them in Teams. Push for concrete examples: "document the covenant workbook before we port it," "review my R script before it ships," "map this cedent's trade descriptions to our categories." Tally the top few live. These become the lab tasks and the skill candidates for Workshop 3.

Workshop 3 · Build a Skill

Open, demo, discussion, and lab

Open (15 min) — protected

W1 + W2 quizzes + skill seeds

Open with BOTH knowledge checks — Workshop 1 then Workshop 2, run live in the poll tool (5 min each), reading each answer aloud. They were cut for time in W2 and the client asked for them back at the start; if timing slips later, cut Teach, never these. Then pull 2–3 use cases from the W2 survey submissions and name them: "These are today's skill seeds."

Pre-recruit two heavy users the day before: "I'd love you to kick off the brainstorm — would you name the first skill you'd build?" No cold calls.
Demo (17 min)

Turn yesterday's demo prompt into a skill — tell, show, recap, schedule

Tell them the four steps, then do them: copy Demo prompt 1 from Lesson 4 §04 (the exact prompt the room watched run on TreatyLayerPricer yesterday) → "turn this into a skill" → file it the one way (one folder per skill, SKILL.md inside) and install → fresh session, grant only the solution-profile-demo folder, and watch one plain sentence fire it. Recap the four steps, then schedule it quarterly with /schedule — TreatyLayerPricer runs quarterly. Keep the finished skills/solution-profile/SKILL.md in a side window as the safety net — "here's one I made earlier" beats live-debugging.

Close with: "Everything you just watched is a key to a door."
Discussion + teams (12 min)

Skill-idea brainstorm, then vault teams

Chat-first brainstorm: everyone types one skill idea from their own week; pre-recruited heavy users go first — no cold call. Group the ideas aloud into a homework menu and save the chat (it's the W4 plugin-demand data). Then a 2-minute litmus on a bad description — vague, first-person, would never trigger. At the 10-min mark, announce breakout room assignments (2–4 per team) and who screen-shares Cowork. Give teams 30 seconds to find their room before break.

Evals before docs — say it twice.
Lab (40 min)

Run the Skill Vault

Ensure all six lab files are shared before breakout rooms open — files are on the lab page as downloads. One driver per team runs Cowork and shares their screen; rest advise. Keep the facilitator view open: live progress per team, hints used, and a Reset for stuck teams. Hint 1 is free; hint 2 adds 2 minutes. Setup and the optional shared-leaderboard backend are in the vault README.

Codes are case-insensitive; the format line in each room's last lab step is the nudge to give first.

When something blocks

Common snags

01
Licenses & SSO
Confirm Claude Cowork access in pre-work. SSO-only sign-in blocks the skill-creator's run_loop optimizer — tune descriptions by hand instead.
02
Asked about the M365 connector
It is not yet available at Gen Re — it's under IT Security review. Say exactly that, and run everything local-folder-first: grant a folder and work from there. All labs are planned local-first.
03
Scheduled tasks & the audit gap
Claude Cowork's scheduled tasks need the machine awake and the app open. And be precise about the June-2026 audit-coverage gap — manage it, re-verify it; don't overstate it.
